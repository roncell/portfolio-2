The math

      
Four points and one number

      
A Bézier curve is a weighted average of its control points. The weights change with a single parameter t that runs from 0 to 1.

    


    

      

        
Bernstein form

        
Each control point gets a polynomial weight. The weights always add up to 1, so the curve stays inside the shape the points make. The ends of the curve touch the first and last points; the middle points only pull.

        

          quadratic
          B(t) = (1−t)²P0 + 2(1−t)t P1 + t²P2
        

        

          cubic
          B(t) = (1−t)³P0 + 3(1−t)²t P1 + 3(1−t)t²P2 + t³P3
        

        
The repo evaluates exactly this, one axis at a time:

        

          
src/utils/interpolation.ts


const cubicBezierP0 = (t, p) => { const k = 1 - t; return k * k * k * p }
const cubicBezierP1 = (t, p) => { const k = 1 - t; return 3 * k * k * t * p }
const cubicBezierP2 = (t, p) => 3 * (1 - t) * t * t * p
const cubicBezierP3 = (t, p) => t * t * t * p

        

      


      

        
de Casteljau's construction

        
The same point can be found with nothing but straight lines. Turn on de Casteljau in the playground to watch it happen at the current t.

        
    
          
  1. Walk the fraction t along each leg of the control polygon. That gives one point fewer.
    2. 
          
  2. Join those points and repeat on the shorter polygon.
    3. 
          
  3. When a single point is left, that point is B(t). The last line drawn is the tangent there.
    4. 
        

        
Engines prefer it because it is numerically steady, and the intermediate points split the curve into two smaller Béziers at t for free.

      


      

        
Moving along the path

        
t is not distance. Equal steps in t bunch up where control points crowd together and spread out where they are far apart, so an object driven by t speeds up and slows down.

        

          velocity
          B′(t) = 3(1−t)²(P1−P0) + 6(1−t)t(P2−P1) + 3t²(P3−P2)
        

        
Bézier-flow gives every segment three seconds and advances t evenly within it, which is what the playground does by default. Watch the speed readout change. Constant speed re-times the traveler by measured arc length, the usual fix in motion planning. The traveler's heading comes from B′(t).

      


      

        
Joining segments

        
In the repo a new segment starts at the previous segment's end point, and dragging that shared point moves both curves. That keeps the path connected (C⁰ continuity).

        
A connected path can still have a kink. For a smooth one, the handle before a joint and the handle after it must sit on one straight line through the joint (G¹), and at equal distances for matching speed (C¹). The Path preset is built that way; drag a handle next to a joint to see the kink appear.

The project

        
A Create React App project in TypeScript. A zustand store holds the list of segments and the play state; React Three Fiber renders them; GSAP drives the animation.

        


src/
├─ App.tsx                    Canvas, camera, grid, OrbitControls
├─ store/index.ts             segments + play state (zustand)
├─ components/
│  ├─ BezierCurveEditor.tsx   handles, gizmo, joint syncing
│  ├─ BezierLineSegment.tsx   drei CubicBezierLine, 50 samples
│  ├─ ControlPoint.tsx        box and sphere handles
│  ├─ useAnimation.ts         GSAP timeline along segments
│  └─ UI/UI.tsx               buttons and curve export
└─ utils/
   ├─ interpolation.ts        Bernstein evaluator
   └─ helpers.ts              live geometry updates, random points
